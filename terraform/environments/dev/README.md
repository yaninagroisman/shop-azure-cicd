# Dev environment (main stack)

Everything the application runs on in Azure. **One `terraform apply` creates
it, one `terraform destroy` removes it** (AD-31); nothing here is meant to
survive a destroy. The state lives in the bootstrap storage account
(`dev.tfstate`).

Status: sub-stages **2a** (network + AKS) and **2b** (ACR, Key Vault,
workload identities) are written; 2c (monitoring) and 2d (Argo CD, public IP)
follow. Nothing is applied yet.

## What 2a creates

| Resource | Notes |
|---|---|
| `rg-shop-dev-swc` | Resource group for this environment |
| `vnet-shop-dev-swc` 10.10.0.0/16, `snet-aks-nodes` 10.10.0.0/22 | Nodes only: pods use the overlay range 192.168.0.0/16 |
| `nsg-shop-dev-swc-aks-nodes` | Inbound 80/443 from the Internet; Azure defaults allow VNet and load balancer probes and deny the rest |
| `aks-shop-dev-swc` | Kubernetes 1.36, Free tier, 2 x Standard_D2ads_v5 (Azure Linux 3, ephemeral OS disk), CNI Overlay + Cilium, Entra ID + Azure RBAC, no local accounts, API server IP allow-list, OIDC + Workload Identity, Key Vault CSI driver, KEDA, Image Cleaner, run command off, no automatic upgrades |
| App Routing Gateway API | Managed Gateway API CRDs + Istio-based implementation (`approuting-istio`), enabled through `azapi_update_resource` because azurerm has no argument for it |
| `id-aks-shop-dev-swc-control-plane`, `-kubelet` | Created before the cluster with their roles (Network Contributor on the subnet, Managed Identity Operator on the kubelet identity) |
| `rg-shop-dev-swc-aks-nodes` | Created and owned by AKS (VM scale set, load balancer, disks) |

## What 2b creates

| Resource | Notes |
|---|---|
| `acrshopdevswc<suffix>` | ACR Basic, no admin user, no anonymous pull. AcrPull: kubelet, Kyverno. AcrPush: `ci` pipeline identity |
| `kv-shop-dev-swc-<suffix>` | Key Vault, RBAC only, soft delete 7 days, no purge protection (destroy + re-create, AD-31), public endpoint without firewall (owner decision) |
| Secrets `mongodb-root-password`, `mongodb-app-password` | Generated by an ephemeral `random_password` and written through `value_wo`: **never in the plan or the state** (AD-36). Rotate: increase `secret_version` in the module call |
| Key `cosign` (EC P-256, sign/verify) | Image signing key (AD-16); the private key never leaves Key Vault. `ci` gets Crypto User on this key only |
| `id-shop-dev-swc-{api,consumer,mongodb,kyverno}` | Workload identities with federated credentials for `shop/api`, `shop/consumer`, `shop/mongodb`, `kyverno/kyverno-admission-controller` |

Kafka users and passwords are not here: Strimzi creates them inside the
cluster (AD-36).

Who can read what:

| Principal | Access |
|---|---|
| `mongodb` | both MongoDB secrets (creates the root and application users) |
| `api`, `consumer` | `mongodb-app-password` only |
| `tf-plan` | both MongoDB secrets (refresh reads values) + Key Vault Reader from the bootstrap |
| `tf-apply`, cluster admins | Secrets Officer + Crypto Officer on the vault (Terraform writes the secrets and the key) |

## Usage

```bash
cd terraform/environments/dev
cp terraform.tfvars.example terraform.tfvars   # real values, git-ignored
cp backend.hcl.example backend.hcl             # git-ignored
terraform init -backend-config=backend.hcl
terraform plan -out=dev.tfplan
terraform apply dev.tfplan

# kubectl access (Entra ID, no static credentials)
$(terraform output -raw kubeconfig_command)

terraform destroy                              # removes the whole environment
```

When your public IP changes, update `api_server_authorized_ip_ranges` and
apply again, otherwise `kubectl` is refused.

## Known limits and accepted risks

- **Quota:** 2 x D2ads_v5 uses the whole 4 vCPU Free Trial quota. Anything
  that adds a node (surge upgrades, node pool rotation, a second pool) fails:
  change the cluster by destroy + apply.
- **No automatic upgrades:** every new apply gets the latest 1.36 patch and
  node image. A cluster left running for weeks does not get security patches
  by itself: destroy and re-create it instead.
- **Single node pool:** system and application pods share it.
- **tf-plan can read the MongoDB passwords:** refreshing a Key Vault secret
  reads its value. Plans run in pull requests; Azure DevOps does not give
  pipelines from forks access to service connections, keep it that way.
- **Key Vault and ACR have public endpoints:** protected by Entra ID + RBAC
  only (Microsoft-hosted agents have no fixed IPs; ACR Basic has no network
  rules).
- **First apply waits 90 s** after the Key Vault role assignments
  (`time_sleep`): new roles need time to reach the Key Vault data plane.
